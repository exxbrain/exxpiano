# Web-интерфейс

## Purpose

Эта возможность предоставляет локальный адаптивный web-интерфейс и JSON API для просмотра состояния устройства и применения настроек инструмента без SSH.

## Requirements

### Requirement: Состояние устройства

Система SHALL отдавать состояние настроек, банков, служб, аудиокарт, активного выхода, версии и идентичности устройства через локальный HTTP API.

#### Scenario: Загрузка web-интерфейса управления

- **WHEN** браузер открывает корневой адрес web-интерфейса устройства
- **THEN** система отдаёт интерфейс, который получает текущее состояние через API и отображает доступные органы управления

#### Scenario: Частично недоступная подсистема

- **WHEN** отдельная команда диагностики или служба недоступна
- **THEN** API возвращает частичное состояние с признаком недоступности вместо отказа всего web-интерфейса

#### Scenario: USB-звуковая карта вынута

- **WHEN** выход синтезатора был USB-картой, и её вынули
- **THEN** состояние выхода отмечает, что карты нет (синтезатор сообщил об этом или карты нет среди подключённых), и web-интерфейс показывает отсутствие звуковой карты вместо прежнего выхода

### Requirement: Применение настроек

Система SHALL валидировать запросы настройки, применять live-параметры немедленно и требовать отдельного явного перезапуска для настроек синтезатора.

#### Scenario: Live-настройка

- **WHEN** клиент изменяет чувствительность, механику или gain допустимым запросом
- **THEN** система сохраняет настройку и применяет её без принудительной перезагрузки банков

#### Scenario: Настройка с перезапуском

- **WHEN** клиент изменяет выход, буфер, полифонию или реверберацию
- **THEN** система сохраняет настройку, но перезапускает синтезатор только после отдельного подтверждённого запроса

### Requirement: MIDI-файлы в web-интерфейсе

Web-интерфейс SHALL показывать в отдельном разделе меню «MIDI-плеер» MIDI-файлы на подключённом накопителе и в библиотеке, позволять импортировать, запускать, останавливать, повторять и удалять их, а также показывать состояние и позицию воспроизведения, не принимая от браузера путей файловой системы.

#### Scenario: Список и состояние

- **WHEN** пользователь открывает раздел «MIDI-плеер»
- **THEN** интерфейс показывает файлы накопителя, файлы библиотеки с длительностью и состояние воспроизведения (ожидание, воспроизводится с позицией, причина остановки)

#### Scenario: Запуск и остановка

- **WHEN** пользователь запускает импортированный файл и затем останавливает его
- **THEN** интерфейс показывает «воспроизводится» с растущей позицией, а после остановки «ожидание»

#### Scenario: Недопустимый запрос

- **WHEN** запрос называет файл, которого нет в списке, содержит путь, неизвестное действие или приходит без токена при включённой защите
- **THEN** API отклоняет его с безопасной ошибкой, не раскрывая внутренних путей

#### Scenario: Переход между разделами не прерывает воспроизведение

- **WHEN** во время воспроизведения пользователь открывает другой раздел (например, «Монитор») или закрывает страницу
- **THEN** воспроизведение продолжается, а раздел «Главная» показывает, что играет и в каком месте

#### Scenario: Занятость

- **WHEN** идёт импорт или переключение банка
- **THEN** запуск воспроизведения и удаление отклоняются как конфликт, а текущая операция продолжается

### Requirement: Состояние загрузки банка

Система SHALL сообщать через API и показывать в web-интерфейсе, какой банк сейчас звучит (превью или основной) и загружается ли основной банк.

#### Scenario: Основной банк грузится

- **WHEN** звучит превью, а основной банк ещё загружается
- **THEN** web-интерфейс показывает, что играет превью и основной банк загружается

#### Scenario: Основной банк загружен

- **WHEN** переход на основной банк выполнен
- **THEN** web-интерфейс показывает основной банк как текущий без пометки о превью
