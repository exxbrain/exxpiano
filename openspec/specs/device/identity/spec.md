# Идентичность устройства

## Purpose

Эта возможность даёт каждой установленной копии постоянную идентичность (ID, имя, setup-сеть) и правильные QR-коды, которые создаёт только само устройство.

## Requirements

### Requirement: Идентификация и QR-коды

Система SHALL показывать номер, имя и статус привязки устройства и создавать QR-коды для подключения к setup-сети и открытия правильного web-интерфейса устройства.

#### Scenario: Код от другого устройства

- **WHEN** web-интерфейс открыт по QR-ссылке с номером, не совпадающим с текущим устройством
- **THEN** интерфейс явно предупреждает пользователя о несовпадении

#### Scenario: Переименование устройства

- **WHEN** пользователь задаёт допустимое hostname из строчных букв, цифр и дефисов
- **THEN** система применяет имя и обновляет сетевую доступность через локальное имя

### Requirement: Скачивание QR-кодов устройства

Web-интерфейс SHALL создавать QR-коды подключения к setup-сети, открытия web-интерфейса setup и открытия web-интерфейса устройства из постоянного installation ID этой установки и SHALL предлагать скачать каждый код как PNG и как SVG с именем файла, содержащим этот ID. Скачивание и создание кодов MUST NOT зависеть от доступности setup-сети в момент открытия web-интерфейса, так как наклейку печатают заранее. Код подключения SHALL содержать SSID и пароль setup-сети из конфигурации с экранированием служебных символов.

#### Scenario: Скачивание кода на устройстве в домашней сети

- **WHEN** пользователь открывает раздел Wi-Fi на устройстве, подключённом к домашней сети
- **THEN** web-интерфейс показывает код подключения к setup-сети с её реальным SSID и паролем, код открытия web-интерфейса setup и код открытия этого web-интерфейса
- **AND** для каждого кода доступны ссылки скачивания PNG и SVG с именем вида `exxpiano-join-wifi-<ID>`

#### Scenario: Печать наклейки

- **WHEN** пользователь нажимает «Печать» в разделе кодов
- **THEN** печатается только карточка с кодами и подписями, без меню и остальных разделов

#### Scenario: Недопустимый вид кода

- **WHEN** клиент запрашивает код неизвестного вида
- **THEN** API отвечает ошибкой и не создаёт изображения

### Requirement: Идентичность установки

Каждая установленная копия SHALL при первом запуске автоматически создавать и постоянно хранить случайный идентификатор в виде 6 шестнадцатеричных символов (24 бита); ранее созданный 16-символьный идентификатор SHALL сохраняться без изменений. Пользователь MUST NOT вводить serial платы или идентификатор установки. Полный идентификатор SHALL входить в setup SSID `exxpiano-Setup-<ID>` и hostname `exxpiano-<id-в-нижнем-регистре>`, а web API и QR-коды SHALL показывать тот же идентификатор. Создание SHALL быть атомарным, а последующие запуски SHALL повторно использовать сохранённое значение.

#### Scenario: Первый запуск клонированных карт

- **WHEN** две карты, записанные из одного ZIP, запускаются впервые
- **THEN** каждая независимо создаёт свой постоянный идентификатор и использует его в setup SSID и hostname

#### Scenario: Повторный запуск

- **WHEN** установка уже имеет сохранённый корректный ID
- **THEN** система сохраняет прежние setup SSID и hostname и не создаёт новый ID

#### Scenario: QR-код другого устройства

- **WHEN** web-интерфейс открыт по QR-коду с ID, отличным от ID текущей установки
- **THEN** web-интерфейс предупреждает, что код принадлежит другому устройству

### Requirement: Образ не создаёт QR-кодов

Сборка SD-образа SHALL NOT создавать QR-коды, наклейки или файлы с ними, потому что идентификатор установки неизвестен до первого включения. Единственным источником QR-кодов SHALL быть web-интерфейс установленного устройства.

#### Scenario: Сборка образа

- **WHEN** выполняется сборка SD-образа
- **THEN** в результате нет QR-кодов, изображений наклеек и скриптов их автономного создания
- **AND** смоук-проверка образа убеждается, что web-интерфейс устройства строит код из сгенерированного installation ID, а не из фиксированного имени
