## MODIFIED Requirements

### Requirement: Универсальный SD-образ

Система SHALL создавать один повторно используемый загрузочный ZIP-образ на базе Alpine Linux aarch64 в sys-режиме для Raspberry Pi 3, 4 и 5 с именем `exxpiano-rpi-v<версия>-alpine-<версия-alpine>-sd.zip`. Образ SHALL предназначаться для непосредственной записи на чистую SD-карту и SHALL содержать приложение, банк фортепиано `full`, банк механики, README и машиночитаемый манифест. Система в образе SHALL собираться только из закреплённых пакетов Alpine и пакетов проекта и MUST NOT содержать компоненты Debian или DietPi. Сборка MUST NOT запрашивать serial платы или другой идентификатор устройства. Первый запуск MUST завершать локальную подготовку без интернета, Ethernet и сохранённой Wi-Fi.

#### Scenario: Один образ для нескольких устройств

- **WHEN** оператор записывает один поставляемый ZIP на несколько чистых SD-карт и впервые запускает их в Raspberry Pi 3, 4 или 5
- **THEN** каждая карта загружается без предварительной установки ОС и без ввода serial платы

#### Scenario: Плата без разъёма 3,5 мм

- **WHEN** образ запускается на Raspberry Pi 5, у которой нет встроенного аналогового выхода
- **THEN** система загружается тем же образом, а синтезатор использует подключённую USB-звуковую карту или завершается ошибкой «нет аудиоустройства» без перехода на HDMI

#### Scenario: Прослеживаемость выпуска

- **WHEN** сборка успешно завершена
- **THEN** имя ZIP содержит версии продукта и Alpine, а README и манифест содержат эти версии, адрес закреплённого репозитория Alpine, отпечатки ключей и список установленных пакетов с версиями

#### Scenario: Обязательный банк отсутствует

- **WHEN** основной или явно выбранный банк фортепиано либо механики отсутствует или непригоден
- **THEN** система завершает сборку ошибкой и не выдаёт ZIP как готовый

#### Scenario: Закреплённый пакет недоступен или изменён

- **WHEN** пакет Alpine нужной версии отсутствует в закреплённом репозитории или его подпись не проходит проверку ключами Alpine
- **THEN** сборка завершается ошибкой и не выдаёт ZIP как готовый

#### Scenario: Секреты сборки

- **WHEN** образу передаются root-пароль и пароль setup-сети
- **THEN** сборщик передаёт их во внутреннюю среду, не включает в аргументы команд и не записывает в журнал

### Requirement: Консоль без запроса пароля

Образ SHALL показывать на локальной консоли информационный экран с ID установки, именем и адресами web-интерфейса управления вместо приглашения входа. Консоль MUST NOT запрашивать логин или пароль, MUST NOT показывать секреты и MUST NOT включать автовход. Администрирование SHALL оставаться доступным по SSH по ключу или паролю root, заданному при сборке.

#### Scenario: Первый запуск с подключённым HDMI

- **WHEN** карта запускается впервые с подключённым монитором
- **THEN** вместо приглашения `login:` на экране информационный экран, который обновляется и не принимает ввод

#### Scenario: Устройство без сети

- **WHEN** у устройства нет адреса
- **THEN** экран называет setup-сеть этой установки и адрес web-интерфейса setup

#### Scenario: Сборка образа

- **WHEN** выполняется сборка или смоук-проверка образа
- **THEN** они проверяют, что на tty1 запускается информационный экран, на консолях нет getty с приглашением входа и нет настроек автовхода

#### Scenario: Сборка без root-пароля

- **WHEN** образ собирается без заданного root-пароля
- **THEN** вход root по паролю по SSH остаётся запрещённым, а README образа объясняет, как добавить ключ
