# Design

## Context

См. `proposal.md`. Сейчас реверберация — это одна настройка `REVERB` (0/1, область `synth`). `exxpiano-run` передаёт её как `synth.reverb.active` (путь с предварительным банком) или `-R` (простой `fluidsynth`). Других параметров нет, и посыл в ревербератор нигде не задаётся.

В FluidSynth уровень эффекта в голосе = генератор `reverbEffectsSend` из SoundFont + стандартный модулятор CC91 → reverb send (до 20 % при CC91 = 127). В наших банках генератора нет, CC91 при старте равен 0 (`fluid_channel_init_ctrl`: строка `EFFECTS_DEPTH1, 40` закомментирована), поэтому посыл равен 0.

MIDI-мост — единственный, кто посылает MIDI в синтезатор. Он уже выставляет пресеты на канале рояля (0) и каналах механики (`PROGRAMS`) в `setup_programs()` и перечитывает `/etc/exxpiano.conf` раз в секунду.

## Goals / Non-Goals

**Goals:**

- Реверберация слышна при включении, без пересборки банков и для любого банка, в том числе импортированного.
- Количество и характер зала настраиваются из web-интерфейса и применяются без перезапуска, если это позволяет FluidSynth.
- Раздел «Эффекты» в интерфейсе, куда позже можно добавить другие эффекты.
- Без включения поведение и нагрузка не меняются.

**Non-Goals:**

- Хорус и другие эффекты (раздел готов для них, но они не входят в это изменение).
- Свёрточная реверберация (импульсные отклики): слишком тяжело для Pi 3.
- Изменение буферов и `PERIODS` (это отдельная работа, которая сейчас идёт).
- Запись посыла в банки (генератор `reverbEffectsSend`).

## Decisions

### 1. Посыл задаёт MIDI-мост через NRPN SoundFont

Мост выставляет посыл на канале рояля и на каждом канале механики в `setup_programs()`, а также при изменении `REVERB_SEND` в `reload_settings()`. При новом подключении к синтезатору сначала идёт CC91 = 0, затем всегда NRPN SoundFont 2.01: CC99 = 120, CC98 = 16 (генератор `reverbEffectsSend`, единица 0,1 %), CC38/CC6 = 8192 + round(`REVERB_SEND` · 500 / 127), после этого RPN null (CC101 = CC100 = 127), чтобы последующий data entry клавиатуры ничего не менял. При повторном выборе пресетов (каждое сканирование) и при изменении `REVERB_SEND` мост повторяет только NRPN, а CC91 не трогает, иначе ручка «Reverb» клавиатуры сбрасывалась бы раз в цикл сканирования. Так `REVERB_SEND` 0–127 даёт посыл 0–50 % с округлением до 0,1 % для банков без собственного `reverbEffectsSend`, включая банки проекта, при CC91 = 0 на обоих путях запуска (сначала был размах 100 %, но при 64 реверберация на слух зашкаливала; при 50 % хвост аккорда громче сухого на 6–11 дБ), так как NRPN — это MIDI, а не API библиотеки. Первый вариант, один CC91 = `REVERB_SEND`, на устройстве почти не слышен: стандартный модулятор FluidSynth CC91 → reverb send имеет размах 20 % (при 40 тихие места La Campanella громче на 0,5 дБ, хвост аккорда при CC91 = 127 громче на 2–3 дБ, при NRPN на 100 % — на 12–15 дБ). Замена стандартного модулятора (`fluid_synth_add_default_mod`, размах 100 %) отклонена: она возможна только на пути `exxpiano-synth.py`, а на запасном пути с простым `fluidsynth` посыл остался бы до 20 %. При выключенной реверберации посыл всё равно выставляется: ревербератор выключен, и посыл ни на что не влияет.

NRPN задаёт смещение генератора. Для импортированных банков с собственным `reverbEffectsSend` посыл моста добавляется к посылу банка без компенсации. Поэтому точный итоговый посыл 0–50 % и сухой звук при `REVERB_SEND=0` для таких банков не гарантируются. Обнуление CC91 убирает вклад его стандартного модулятора, но не генератор банка. Настройка `self.reverb_send` и поставляемые банки остаются прежними.

Альтернативы:
- Генератор `reverbEffectsSend` в банках: требует пересборки, не работает для импортированных банков. Отклонено.
- `cc 0 91 N` через командный канал из `exxpiano-run` или `exxpiano-synth.py`: значение теряется при каждом сбросе контроллеров, а мост и так владеет каналами и восстанавливает их после переподключения. Отклонено.

### 2. CC91 от клавиатуры и из MIDI-файлов

Мост передаёт CC91 с клавиатуры как есть (на канал рояля): ручка «Reverb» на клавиатуре добавляет до 20 % поверх посыла из настроек, до переподключения к синтезатору. CC91 = 0 мост шлёт только при новом подключении; при повторном выборе пресетов (каждое сканирование) и при изменении `REVERB_SEND` он повторяет только NRPN, иначе ручка клавиатуры сбрасывалась бы раз в цикл сканирования. MIDI-плеер передаёт мосту только ноты и педаль, поэтому CC91 из файла до синтезатора не доходит, и файл звучит с посылом из настроек. Восстанавливать посыл после остановки плеера не нужно.

### 3. Параметры зала: настройки FluidSynth `synth.reverb.*`

`REVERB_ROOM` → `synth.reverb.room-size`, `REVERB_DAMP` → `synth.reverb.damp`, `REVERB_WIDTH` → `synth.reverb.width`, `REVERB_LEVEL` → `synth.reverb.level`. Все значения 0.0–1.0. `exxpiano-run` передаёт их через `-o` на обоих путях запуска. Начальные значения подбираются на слух на Pi (задача 4.2). Отправная точка: посыл 64 (середина, 25 %), размер 0.6, глушение 0.4, ширина 0.8, уровень 0.7.

В интерфейсе показываются включение, «Количество» (посыл), «Размер зала» и «Глушение». Ширина и уровень остаются только в файле, чтобы не перегружать телефонный экран.

### 4. Применение на ходу

Новая область настроек `effects`. Web-сервер сохраняет значение атомарно, как и раньше, и затем:
- `REVERB`, `REVERB_ROOM`, `REVERB_DAMP`, `REVERB_WIDTH`, `REVERB_LEVEL` отправляет в `CMD_FIFO` как `set synth.reverb.active 1` / `set synth.reverb.room-size 0.6` и т. д. Так уже работает `set synth.gain`.
- `REVERB_SEND` подхватывает мост при перечитывании файла (как `FX_ARGS`).

В FluidSynth 2.x эти настройки помечены как изменяемые на ходу. Это нужно подтвердить на версии из Alpine 3.24 (задача 4.1). Если команда не прошла (канала нет, синтезатор не запущен), настройка всё равно сохранена, а ответ API говорит, что нужен перезапуск, как сейчас для `synth`.

### 5. Где хранить посыл

`REVERB_SEND` хранится отдельной строкой, а не в `FX_ARGS`, и не запоминается по банкам. Зал — это свойство помещения и вкуса пользователя, а не банка. Мост читает значение через `exxpianoconf.get_settings()`, как и остальные свои параметры.

### 6. Нагрузка

Ревербератор FluidSynth (FDN) считается в потоке, который смешивает голоса и отдаёт звук в ALSA, а не в потоках `synth.cpu-cores`. Он добавляет постоянную нагрузку, даже когда клавиши не нажаты. По умолчанию реверберация выключена. В подсказке у включателя написано, что при треске нужно увеличить число периодов.

## Risks / Trade-offs

- [Треск на 3,5 мм с `PERIODS=2` после включения] → по умолчанию выключено; замер на Pi 3 B с La Campanella (задача 4.3); в документации — совет `PERIODS=3`.
- [FluidSynth из Alpine не применяет `synth.reverb.*` на ходу] → откат на «требуется перезапуск»; поведение не хуже текущего.
- [Резкий скачок при включении на ходу (хвост, щелчок)] → проверить на слух; если мешает, сначала выставлять посыл 0, затем включать, затем возвращать посыл.
- [Клавиатура шлёт CC91 = 0 при старте или сбросе] → значение действует до следующего движения ручки или переподключения; если это будет мешать, CC91 с клавиатуры можно фильтровать (отдельное решение).
- [Предварительный банк и переход на основной] → настройка NRPN и CC91 принадлежит каналу, поэтому замена SoundFont её не сбрасывает; итоговый посыл может измениться, если новый банк задаёт собственный `reverbEffectsSend`; проверить тестом и на устройстве.

## Migration Plan

1. Новые строки отсутствуют в файлах старых установок: используются значения по умолчанию (`exxpianoconf` и `exxpiano-run`). `REVERB` сохраняет смысл.
2. У тех, у кого `REVERB=1` уже стоит, после обновления реверберация станет слышна (посыл 64). Это ожидаемое исправление, его нужно указать в CHANGELOG.
3. Откат — `REVERB=0`; данные не затрагиваются.

## Open Questions

- Окончательные значения по умолчанию для зала (подбираются на слух на Pi).
- Нужны ли готовые пресеты («Комната», «Зал», «Собор») вместо ползунков размера и глушения. Пока ползунки; пресеты можно добавить без изменения формата файла.
