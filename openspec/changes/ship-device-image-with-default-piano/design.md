# Design

## Context

Продукт поставляется как готовое устройство. Образ должен содержать DietPi, приложение и банки и записываться на чистую SD-карту. Персональная сборка по serial усложняет производство, требует заранее сопоставить карту и плату и не нужна после удаления аппаратной блокировки. Одновременно клонированные карты не должны создавать одинаковые hostname и setup SSID.

## Goals / Non-Goals

**Goals:**

- один универсальный образ для Raspberry Pi 2/3/4 ARMv8;
- отсутствие ручного ввода serial или ID;
- стабильная уникальная идентичность каждой установки;
- автономный первый запуск с уникальной setup-сетью;
- обязательные стандартные банки и проверяемые метаданные выпуска.

**Non-Goals:**

- аппаратная лицензия или привязка карты к плате;
- центральный реестр отдельных установок;
- runtime-импорт пользовательских банков;
- публикация `.deb` как самостоятельного продукта.

## Decisions

### 1. Универсальный артефакт

Сборщик создаёт один `exxpiano-rpi234-v<VERSION>-dietpi-<DIETPI_VERSION>-sd.zip`. Он не принимает serial, имя устройства, список плат или номер и не записывает идентичность установки внутрь образа. В манифест входят версии, хеши, банки и признак `generated-at-first-boot`.

### 2. ID создаётся на установленной копии

Первое обращение к идентичности создаёт 8 криптографически случайных байт и сохраняет их как 16 hex-символов верхнего регистра в `/var/lib/exxpiano/installation-id`. Файл создаётся через `O_EXCL`, поэтому параллельный запуск служб не создаёт два разных значения. Существующий корректный ID никогда не заменяется автоматически; повреждённый файл даёт диагностируемую ошибку.

64-битное пространство даёт пренебрежимо малую вероятность коллизии для ожидаемого числа устройств. Полный ID, а не короткий суффикс, используется в сети и интерфейсе.

### 3. Сеть и hostname выводятся из ID

Setup SSID равен `exxpiano-Setup-<ID>` и укладывается в лимит 32 байта. Начальный generic hostname при первом старте меняется на `exxpiano-<id-в-нижнем-регистре>`. ID также возвращается web API и включается в QR URL как `?d=<ID>`; несовпадение параметра с текущим ID показывает предупреждение.

Пользователь может позже задать дружелюбный hostname, но ID и setup SSID остаются стабильными.

### 4. First boot и комплектация

DietPi выполняет только локальную подготовку, не ждёт сеть и не запускает обязательное online-обновление. `exxpiano-wifi` владеет `wlan0`. Образ не выпускается без приложения, `piano.sf2`, `mech.sf2` или читаемой версии DietPi.

### 5. Проверка

Обычные изменения проверяются быстрыми Python и shell-тестами. Полная сборка образа не запускается без изменений конвейера или отдельного решения о выпуске. Аппаратная проверка на Pi 2/3/4 остаётся обязательной перед подтверждением поддержки каждой модели.

## Risks / Trade-offs

- Очень редкая случайная коллизия ID устраняется перепрошивкой одной установки до ввода в эксплуатацию; использование полного 64-битного ID делает риск приемлемым.
- Копирование уже загруженной карты копирует и ID. Производственный мастер MUST быть исходным ZIP, а не снимком однажды запущенной карты.
- Повреждение файла ID не маскируется новым значением, чтобы сеть и hostname не менялись незаметно.

## Migration Plan

1. Удалить параметры serial/number и реестр из сборщика.
2. Добавить постоянный ID и перевести Wi-Fi, hostname, API и QR на него.
3. Обновить артефакты, тесты, OpenSpec и документацию.
4. Записать один ZIP на несколько карт и проверить разные ID, затем выполнить аппаратную матрицу Pi 2/3/4.
