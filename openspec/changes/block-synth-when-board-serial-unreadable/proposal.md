# Proposal

## Why

При `DEVICE_LOCK=1` и настроенном `DEVICE_SERIAL` текущая реализация разрешает запуск, если серийный номер фактической платы невозможно прочитать. Это fail-open поведение противоречит базовой спецификации `piano-runtime` и лишает блокировку смысла именно тогда, когда принадлежность платы нельзя подтвердить.

## What Changes

- **BREAKING**: заблокировать запуск синтезатора, когда включена блокировка, настроена корректная привязка, но серийный номер фактической платы не прочитан.
- Возвращать для этого случая тот же постоянный код `EX_CONFIG`/78, который уже используется для несовпадающей платы и включён в `RestartPreventExitStatus` systemd.
- При включённой блокировке также завершаться с постоянным отказом, если обязательный serial-checker невозможно запустить, вместо обхода проверки.
- Сохранить текущее поведение для незаблокированной карты и для конфигурации без корректного `DEVICE_SERIAL`.
- Обновить unit- и shell-интеграционные тесты так, чтобы unreadable serial проверялся как отказ без запуска FluidSynth.
- Синхронизировать docstring, комментарии конфигурации и пользовательскую документацию с fail-closed поведением.
- Проверка на реальной Raspberry Pi не требуется для принятия изменения: отсутствие serial детерминированно моделируется тестовым `EXXPIANO_CPUINFO`; аппаратную проверку можно выполнить дополнительно, но она не является неподтверждённым заявлением о совместимости.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Требуемое поведение уже определено в `piano-runtime` требованиями «Привязка карты к плате» и сценарием «Серийный номер недоступен»; change устраняет расхождение реализации со спецификацией.

## Impact

- `pi/deviceid.py`: ветка `locked + bound + unreadable actual serial` возвращает 78 и диагностическое сообщение об отказе.
- `pi/exxpiano-run`: serial-check становится обязательным при включённой блокировке; ошибка чтения или запуска checker преобразуется в постоянный exit 78.
- `tests/test_deviceid.py`, `tests/test_audio_select.py`: старое fail-open ожидание заменяется fail-closed тестами функции и запуска shell-wrapper.
- `pi/exxpiano.service`, `pi/exxpiano.conf`, README и build-image docs: формулировки охватывают как несовпадение, так и невозможность подтверждения serial.
- Миграция данных и изменение формата конфигурации не требуются.
