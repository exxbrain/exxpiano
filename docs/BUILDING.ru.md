# Сборка exxpiano самому

[English](BUILDING.md) | Русский

Только для тех, кто собирает банки и образ сам или работает с кодом. Чтобы играть, достаточно готового образа из [последнего релиза](https://github.com/exxbrain/exxpiano/releases/latest) (см. [README](../README.ru.md)). Сам образ SD-карты: [BUILD-IMAGE.ru.md](BUILD-IMAGE.ru.md).

## Что понадобится для сборки

| | |
|---|---|
| Mac или Linux для банков | `python3`, `ffmpeg` (вместе с `ffprobe`), `curl`, `tar` с xz; ~2 ГБ места |

## Развёртывание кратко

Поставляемый продукт — готовое устройство с уже установленным exxpiano. Один полный образ Alpine Linux используется для всех Raspberry Pi 3, 4 и 5; отдельный пакет или архив-установщик не является форматом поставки.

1. Один раз соберите банки: `scripts/make-soundfonts.sh -p full`, `-p lite` и `-p preview` (следующие берут уже скачанные сэмплы). Получатся обязательные `build/piano-full.sf2`, `build/mech.sf2` и `build/piano-preview.sf2` и уменьшенный `build/piano-lite.sf2` для плат с 512 МБ.
2. Соберите подписанные пакеты: `scripts/build-apks.py`, затем универсальный образ: `scripts/build-sd-image.py`. 
3. Запишите `exxpiano-rpi-v<VERSION>-alpine-<ВЕРСИЯ_ALPINE>-sd.zip` прямо на чистую SD-карту через Raspberry Pi Imager или balenaEtcher.
4. Вставьте карту в Raspberry Pi 3, 4 или 5 и включите питание.

Полная процедура и текущий статус проверок описаны в [руководстве по сборке образа](BUILD-IMAGE.ru.md).
Теги версий с именем `v<VERSION>` собирают этот образ и публикуют его вместе с манифестом, README и контрольными суммами как assets GitHub Release.

### Перед большим релизом: основные функции на настоящей Raspberry Pi

Перед каждым большим релизом (новая старшая или средняя версия, `X.Y.0`) запишите на чистую карту тот образ, который пойдёт в релиз, и проверьте на Raspberry Pi 3 Model B с USB MIDI-клавиатурой. Автотесты и контейнеры этого не заменяют: в них нет звуковой карты, клавиатуры и радио. Результаты (что пробовали, на какой плате, цифры) запишите в раздел релиза в CHANGELOG; что не пробовали, там тоже сказано.

1. **Пианино:** клавиши звучат через разъём 3,5 мм с полным банком и механикой (молоточки, демпферы, педаль); смена банка в web-интерфейсе работает; MIDI-проигрыватель играет демонстрационную пьесу.
2. **Превью:** от подачи питания, если нажимать клавишу снова и снова, первая нота звучит не позже чем через **15 с** (секундомер от подключения питания); превью слышно, в том числе через вход, который берёт левый канал минус правый (кабель TRS в балансный вход микшера); переход на полный банк без паузы; во время смены банка звучит превью.
3. **Wi-Fi:** без кабеля и без сохранённых сетей появляется сеть настройки `exxpiano-Setup-<ID>`; телефон подключается к ней, страница открывается, Pi подключается к домашней сети и доступен по `exxpiano-<id>.local`; если забыть эту сеть, Pi уходит из неё, а сеть настройки работает ещё 5 минут.

## Собрать звуковые банки (на Mac/Linux)

Сами банки в репозитории не хранятся (сотни мегабайт, лицензия Salamander — CC-BY, см. [NOTICE.md](../NOTICE.md)).
Их делает скрипт из оригинального архива:

```bash
scripts/make-soundfonts.sh -p full -o build          # скачает ~412 МБ и соберёт
```

Если Salamander у вас уже распакован (папка с `SalamanderGrandPianoV3Retuned.sfz`), укажите её: `-s /путь/к/папке`.

Результат: `build/mech.sf2` (36 МБ) и `build/piano-<пресет>.sf2`.

### Выбор пакета сэмплов (`-v`)

Salamander опубликован на [FreePats](https://freepats.zenvoid.org/Piano/acoustic-grand-piano.html) в нескольких пакетах. Сборщики
находят файлы сэмплов по путям из SFZ и приводят всё к 44.1 кГц / 16 бит, поэтому готовые банки получаются одного размера
независимо от пакета; источник влияет только на точность преобразования и на объём загрузки.

```bash
scripts/make-soundfonts.sh -p full -v 48k24 -o build     # взять пакет WAV 48 кГц / 24 бит
```

| `-v` | Пакет | Загрузка | Статус |
|---|---|---|---|
| `44k16` (по умолчанию) | SFZ WAV, 44.1 кГц 16 бит | 412 МБ | собирался и работает на настоящей Pi |
| `48k24` | SFZ WAV, 48 кГц 24 бита | 1.26 ГБ | проверен на копии набора `44k16`, преобразованной в этот формат (звук совпадает с `44k16`, разница на 67 дБ ниже сигнала); реальная загрузка 1.26 ГБ **не** пробовалась |
| `48k24-flac` | SFZ FLAC, 48 кГц 24 бита (пакет от 2020-06-02) | 742 МБ | **экспериментальный**: механизм (FLAC, другие папки) проверен на синтетическом наборе, но структура реального архива и имя SFZ не изучались; если SFZ не найден, укажите `-n ИМЯ` |

Для любого другого SFZ-пакета Salamander есть `-u URL` (и `-n ИМЯ`, если SFZ-файл называется иначе). Таблица слоёв в сборщике
рассчитана на 16 слоёв громкости набора V3. На FreePats есть и готовый SF2 Salamander; здесь он не используется, потому что в нём нет
пресетов механики и уменьшения слоёв.

| Пресет | Размер в RAM Pi | Что это | `GAIN` | Проверено на Pi 3 |
|---|---|---|---|---|
| `lite` | ~250 МБ | 6 слоёв, стерео, хвосты 9 с | 0.6 | близкий вариант (нагрузка CPU ~30%) |
| `full` | ~700 МБ | 14 слоёв, стерео, хвосты 12 с; для платы с 1 ГБ (резерв памяти для таких плат 200 МБ). **Не для 512 МБ** | 0.6 | запускается и играет на плате с 1 ГБ; на слух звучит лучше прежнего банка на 390 МБ и значительно лучше готовой облегчённой версии Salamander из официальной библиотеки (один слушатель, не слепой тест); свободная память после загрузки не записана, смотрите `free -m` |

Файл целиком читается в оперативную память. У Pi 3 Model B/B+ её 1 ГБ, а у **Pi 3 Model A+ всего 512 МБ (около 414 МБ доступно)**, и `full` там не помещается:
на реальной Pi 3 A+ ядро убивало FluidSynth с банком 390 МБ на 370 МБ (`Out of memory: Killed process (fluidsynth)`), и служба перезапускалась снова и снова. Берите `lite`
(237 МБ; **проверен на реальной Pi 3 A+, работает**, в том числе автоматический выбор при первом запуске). `lite` против `full`: 6 слоёв громкости
вместо 14, хвосты 9 с вместо 12 с, самая тихая нота громче (−12 дБ вместо −17 дБ), поэтому динамический диапазон немного меньше. Свободную память проверьте сами (`free -m`, столбец `available`).

## Обновление работающей Pi

```bash
scripts/deploy-to-pi.sh 192.168.1.95        # вход под root по SSH-ключу (или root@host)
```

Скрипт собирает подписанные пакеты, отправляет их на Pi и обновляет там через `apk`: сохраняет `/etc/exxpiano.conf` (новая версия по умолчанию
кладётся рядом как `exxpiano.conf.apk-new`), хранит пакет прежней версии, проверяет, что синтезатор и мост поднялись и продолжают работать, и сам откатывается,
если нет, ставя тот пакет снова (`deploy/upgrade-on-pi.sh`, вручную: `deploy/rollback-on-pi.sh`). Пакет с подписью, которой устройство не доверяет, отклоняется
до каких-либо изменений; для вашего ключа разработки нужен `EXXPIANO_DEV_UNTRUSTED=1`. Звуковые банки не затрагиваются. Состояние устройства показывает
`deploy/check-on-pi.sh` (`ssh root@<устройство> sh -s < deploy/check-on-pi.sh`).

**Пароли при обновлении.** Скрипт входит по вашему SSH-ключу и не спрашивает ни пароль, ни подтверждение ключа хоста. На устройстве, где вашего ключа ещё нет (новая карта, переустановленный образ), он ставит ключ через `ssh-copy-id`: пароль SSH спрашивается **один этот раз**. Ключ на вашем компьютере нужен (`ls ~/.ssh/*.pub`; если нет: `ssh-keygen -t ed25519`). Если ключ поставить не удалось, скрипт переходит на обычный вход по паролю (спросит один раз), а не останавливается: на самом устройстве, у которого нет монитора, никогда ничего не спрашивается. Пароль — пароль root, заданный при сборке образа (`SD_PASSWORD`); образ без пароля принимает только ключи. Изменившийся ключ хоста по-прежнему останавливает скрипт: это повод проверить, а не обойти.

## Где что лежит

Всё в этой одной папке. Git игнорирует большие генерируемые части, поэтому их нельзя закоммитить (хук коммита дополнительно отклоняет любой файл больше 5 МБ):

| Папка | Что | В git |
|---|---|---|
| `pi/`, `tools/`, `scripts/`, `deploy/`, `alpine/`, `packaging/`, `tests/`, `docs/` | программа, закреплённая основа Alpine, сборщик образа, пакеты, тесты | да |
| `build/` | собранные банки (`mech.sf2`, `piano-<пресет>.sf2`), скачанный Salamander в `build/salamander-44k16/`, старые банки в `build/archive/` | нет |
| `dist/sd/` | универсальный полный SD-образ и его метаданные | нет |

## Посмотреть web-интерфейс без Raspberry Pi

```bash
python3 scripts/demo-web.py --open            # http://127.0.0.1:8080/
```

Настоящий web-интерфейс и настоящий код сервера работают на вашем компьютере с **имитацией устройства** (службы, процессор и температура, которые меняются, сети Wi-Fi,
три банка, звуковой интерфейс). Двигайте ползунки, меняйте банк, переименовывайте устройство, добавляйте и забывайте сети Wi-Fi (имя с «fail» не подключится, «Cafe» открытая),
сканируйте QR-коды. Параметры: `--mode ap` (режим настройки: устройство без сети), `--installation-id 012ABC`, `--hostname ИМЯ`,
`--throttled`, `--bind 0.0.0.0` (посмотреть с телефона в той же сети), `--token СЕКРЕТ`. Ничего не пишется за пределами временной папки.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Проверяют логику механики (`FXCore`), службы OpenRC и пакеты Alpine как файлы, сборщик образа и то, что сборщики SF2 принимают разные пакеты сэмплов
(44.1 кГц/16 бит и 48 кГц/24 бита, WAV и FLAC, разные структуры папок; для этой части нужен `ffmpeg`, без него она пропускается).
Оборудование не нужно. Обмен с ALSA в тестах не покрыт (проверялся на реальной Pi), а качество звука собранного банка проверялось
вручную через FluidSynth. Пакеты, службы, обновление с откатом и сам образ проверяются в контейнерах Alpine (Docker): `scripts/test-openrc-services.sh`,
`scripts/test-apk-upgrade.sh`, `scripts/test-sd-image-pipeline.sh`; проверки кода из CI запускает `scripts/lint.sh`.

`scripts/lint.sh` запускает проверки кода: `ruff` для Python (ошибки и чистота кода: вероятные баги, лишний код, незакрытые файлы, порядок импортов, имена; правила и исключения под стиль проекта — в `ruff.toml`), `shellcheck` для shell-скриптов и проверку, что в git нет файлов больше 5 МБ. CI запускает тесты и эти проверки при каждом push и pull request (`.github/workflows/build.yml`).
