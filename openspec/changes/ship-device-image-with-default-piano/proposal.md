# Proposal

## Why

Продуктом является готовое устройство, поэтому основной результат сборки должен быть полным записываемым образом DietPi с уже установленным фортепиано. Один образ должен безопасно использоваться для нескольких устройств без предварительного чтения или ручного ввода serial платы. При этом устройства должны различаться в сети и при установке.

## What Changes

- **BREAKING**: исключить отдельные `.deb` и ZIP/TAR.GZ-инсталлятор поверх DietPi из публичных результатов сборки.
- Сделать один универсальный SD-образ для Raspberry Pi 2/3/4 ARMv8 основным поставляемым артефактом.
- Именовать ZIP `exxpiano-rpi234-v<версия>-dietpi-<версия-dietpi>-sd.zip`; имя MUST NOT содержать serial платы или ID отдельной установки.
- Сборка и первый запуск MUST NOT требовать ввода serial платы.
- Каждая установка SHALL при первом запуске атомарно создать постоянный случайный 64-битный ID в виде 16 hex-символов.
- Использовать полный ID в уникальной setup-сети `exxpiano-Setup-<ID>`, hostname `exxpiano-<id>` и QR-кодах; web-интерфейс SHALL показывать ID и предупреждать о коде другой установки.
- **BREAKING**: удалить runtime-привязку карты к плате, `DEVICE_LOCK`, персонализацию по serial и учёт отдельных карт в реестре сборки.
- Включать DietPi, приложение, стандартный банк фортепиано и банк механики; отсутствие обязательного банка MUST блокировать выпуск.
- Первый запуск MUST работать без интернета, Ethernet и сохранённой Wi-Fi; `exxpiano-wifi` SHALL поднимать уникальную setup-сеть.
- Фиксировать версии продукта и DietPi, SHA-256 основы и результата в README и манифесте выпуска.
- Запускать только быстрые тесты для обычных изменений; полный образный конвейер нужен при его изменении или перед выпуском.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `provisioning-and-upgrades`: заменить персональные образы и реестр карт универсальным образом и автоматически создаваемой идентичностью установки.
- `piano-runtime`: удалить привязку запуска к плате.

## Impact

- Затрагиваются сборщик и имя SD-образа, first boot, Wi-Fi supervisor, hostname, web API и QR-коды, тесты, CI и документация.
- Runtime-импорт пользовательских банков относится к change `import-banks-from-usb` и не влияет на начальный образ.
- Большие банки и производные файлы по-прежнему не отслеживаются в Git.
- Контейнерные проверки покрывают формат артефакта и логику ID; первый старт, MIDI и звук всё ещё требуют проверки на Raspberry Pi 2, 3 и 4.
