# Сборка производственного образа SD-карты

[English](BUILD-IMAGE.md)

Продукт — готовое устройство exxpiano. Формат поставки — один полный образ DietPi для одной платы Raspberry Pi, который записывается прямо на чистую SD-карту. Отдельный Debian-пакет или архив-установщик не является пользовательским форматом поставки.

Образ предназначен для семейства DietPi `RPi234 ARMv8`: поддерживаемых этим базовым образом Raspberry Pi 2, 3 и 4. Фактическая аппаратная проверка учитывается отдельно для каждой модели; автоматический тест на образе-заменителе не считается аппаратной проверкой.

## Что понадобится

- Python 3 и запущенный Docker (либо Linux с root и флагом `--no-docker`).
- Официальный базовый образ `DietPi_RPi234-ARMv8-*.img.xz`.
- Обязательные стандартные банки `build/piano-standard.sf2` и `build/mech.sf2`. Один раз соберите их командой `scripts/make-soundfonts.sh -p standard`.
- Серийный номер каждой целевой платы. Прочитайте поле `Serial` из `/proc/cpuinfo`; сборщик нормализует 8–16 шестнадцатеричных цифр до 16 строчных цифр.

При отсутствии образа DietPi, любого банка или serial сборка останавливается до изменения основы. Готовый образ всегда заблокирован на свою плату. Если устройство не может прочитать serial во время работы или читает другой serial, синтезатор MUST NOT запускаться.

## Одна плата

```bash
python3 scripts/build-sd-image.py \
  --dietpi ~/Downloads/DietPi_RPi234-ARMv8-Trixie.img.xz \
  --serial 00000000d2f2f1de \
  --number auto \
  --password 'пароль DietPi, не короче 8 символов' \
  --ap-password 'пароль сети настройки' \
  --country RU --timezone Europe/Moscow \
  --note 'владелец устройства или производственная пометка'
```

Команда автоматически использует стандартные банки. Флаги `--piano FILE.sf2` и `--mech FILE.sf2` переопределяют их для намеренного варианта. Продуктового режима без банков и необязательного переключателя блокировки нет.

`--number auto` выбирает следующий свободный номер из `registry/devices.csv`; `--number serial` использует последние четыре цифры serial; номер также можно указать явно. Флаг `--dry-run` проверяет входные данные и показывает план, ничего не создавая.

## Партия плат

Создайте `boards.csv`:

```csv
serial,number,name,note
00000000d2f2f1de,,,Иван
00000000aaaabbbb,0042,exxpiano-kitchen,Ольга
100000001234cdef,,,
```

Запустите:

```bash
python3 scripts/build-sd-image.py \
  --dietpi ~/Downloads/DietPi_RPi234-ARMv8-Trixie.img.xz \
  --serials boards.csv \
  --password 'пароль DietPi' --ap-password 'пароль сети настройки' \
  --country RU --timezone Europe/Moscow
```

Все строки проверяются до начала первой сборки. Для каждого serial создаётся отдельный заблокированный образ.

## Результат и прослеживаемость

Для каждой платы в `dist/sd/<номер>/` появляются:

- `exxpiano-rpi234-v<VERSION>-dietpi-<DIETPI_VERSION>-<номер>-sn-<serial>-sd.zip` — полный образ для записи;
- `manifest-<номер>.json` — версия продукта, версия и SHA-256 основы DietPi, нормализованные номер и serial, SHA-256 образа и сведения о банках;
- `README-<номер>.txt` — та же идентичность устройства и инструкция по записи;
- `sticker/` — печатные QR-коды настройки.

Версия продукта берётся из `VERSION`. Версия DietPi читается из `dietpi/.version` внутри базового образа. Если метаданные отсутствуют или непригодны, выпускной артефакт не создаётся. Та же идентичность записывается в `registry/devices.csv`.

## Запись на чистую SD-карту

1. В Raspberry Pi Imager выберите **Use custom** и укажите сам ZIP; распаковывать его не нужно. balenaEtcher также умеет записать ZIP напрямую.
2. Выберите чистую SD-карту и запишите образ.
3. Вставьте карту именно в плату, serial которой указан в имени файла, подключите Ethernet для первой настройки DietPi и включите питание.
4. После настройки откройте `http://exxpiano-<номер>.local:8080/`. Если обычная сеть не настроена, используйте сеть `exxpiano-Setup-<номер>` и QR-коды на наклейке.

## Статус проверок

`scripts/test-sd-image-pipeline.sh` прогоняет полный конвейер на небольшом образе-заменителе с раскладкой DietPi. `scripts/sd-smoke-test.sh` перечитывает результат и проверяет загрузочные файлы DietPi, установленное приложение, оба банка, их конфигурацию и блокировку по serial. CI запускает этот конвейер, но не публикует персональные образы или пакетные артефакты.

Это не доказывает работу на реальном оборудовании. Перед выпуском нужно записать и проверить отдельные карты на Raspberry Pi 2, 3 и 4: первую загрузку, MIDI-вход, звук, стандартные банки фортепиано и механики, а также автономную повторную загрузку. Результаты фиксируются отдельно для каждой модели.
