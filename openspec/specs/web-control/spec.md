# Веб-управление

## Purpose

Эта возможность предоставляет локальный адаптивный web-интерфейс и JSON API для настройки инструмента, выбора банков, диагностики и идентификации устройства без SSH.

## Requirements

### Requirement: Состояние устройства

Система SHALL отдавать состояние настроек, банков, служб, аудиокарт, активного выхода, версии и идентичности устройства через локальный HTTP API.

#### Scenario: Загрузка web-интерфейса управления

- **WHEN** браузер открывает корневой адрес web-интерфейса устройства
- **THEN** система отдаёт интерфейс, который получает текущее состояние через API и отображает доступные органы управления

#### Scenario: Частично недоступная подсистема

- **WHEN** отдельная команда диагностики или служба недоступна
- **THEN** API возвращает частичное состояние с признаком недоступности вместо отказа всего web-интерфейса

### Requirement: Применение настроек

Система SHALL валидировать запросы настройки, применять live-параметры немедленно и требовать отдельного явного перезапуска для настроек синтезатора.

#### Scenario: Live-настройка

- **WHEN** клиент изменяет чувствительность, механику или gain допустимым запросом
- **THEN** система сохраняет настройку и применяет её без принудительной перезагрузки банков

#### Scenario: Настройка с перезапуском

- **WHEN** клиент изменяет выход, буфер, полифонию или реверберацию
- **THEN** система сохраняет настройку, но перезапускает синтезатор только после отдельного подтверждённого запроса

### Requirement: Защита токеном

Если настроен веб-токен, система SHALL требовать его для всех API, включая чтение состояния и операции Wi-Fi, но SHALL продолжать отдавать оболочку web-интерфейса для ввода токена.

#### Scenario: Неверный токен

- **WHEN** запрос к API не содержит настроенный токен или содержит другое значение
- **THEN** система отвечает отказом авторизации и не выполняет операцию

### Requirement: Мониторинг

Система SHALL предоставлять текущую и ограниченную по размеру историю загрузки CPU, температуры, частоты, памяти, throttling, нагрузки процессов пианино и фактических параметров активного аудиопотока.

#### Scenario: Дозагрузка точек графика

- **WHEN** клиент запрашивает мониторинг с отметкой времени последней известной точки
- **THEN** система возвращает текущий снимок и только более новые точки истории

### Requirement: Идентификация и QR-коды

Система SHALL показывать номер, имя и статус привязки устройства и создавать QR-коды для подключения к setup-сети и открытия правильного web-интерфейса устройства.

#### Scenario: Код от другого устройства

- **WHEN** web-интерфейс открыт по QR-ссылке с номером, не совпадающим с текущим устройством
- **THEN** интерфейс явно предупреждает пользователя о несовпадении

#### Scenario: Переименование устройства

- **WHEN** пользователь задаёт допустимое hostname из строчных букв, цифр и дефисов
- **THEN** система применяет имя и обновляет сетевую доступность через локальное имя

### Requirement: Скачивание QR-кодов устройства

Web-интерфейс SHALL создавать QR-коды подключения к setup-сети, открытия web-интерфейса setup и открытия web-интерфейса устройства из постоянного installation ID этой установки и SHALL предлагать скачать каждый код как PNG и как SVG с именем файла, содержащим этот ID. Скачивание и создание кодов MUST NOT зависеть от доступности setup-сети в момент открытия web-интерфейса, так как наклейку печатают заранее. Код подключения SHALL содержать SSID и пароль setup-сети из конфигурации с экранированием служебных символов.

#### Scenario: Скачивание кода на устройстве в домашней сети

- **WHEN** пользователь открывает раздел Wi-Fi на устройстве, подключённом к домашней сети
- **THEN** web-интерфейс показывает код подключения к setup-сети с её реальным SSID и паролем, код открытия web-интерфейса setup и код открытия этого web-интерфейса
- **AND** для каждого кода доступны ссылки скачивания PNG и SVG с именем вида `exxpiano-join-wifi-<ID>`

#### Scenario: Печать наклейки

- **WHEN** пользователь нажимает «Печать» в разделе кодов
- **THEN** печатается только карточка с кодами и подписями, без меню и остальных разделов

#### Scenario: Недопустимый вид кода

- **WHEN** клиент запрашивает код неизвестного вида
- **THEN** API отвечает ошибкой и не создаёт изображения
