# Proposal

## Why

Первичная настройка сейчас требует подключить телефон к setup Wi-Fi устройства и затем вручную вернуться в домашнюю сеть. BLE-подготовка позволит передать параметры домашней Wi-Fi напрямую с телефона, сохранив автономный запуск и существующую setup-сеть как резервный способ восстановления.

## What Changes

- Добавить BLE GATT-сервис настройки, рекламирующий устройство по постоянному installation ID и доступный без подключения телефона к Wi-Fi устройства.
- Добавить мобильное приложение на TypeScript для Android и iOS: поиск ближайших exxpiano, выбор устройства по ID, получение списка Wi-Fi, ввод параметров сети и показ результата подключения.
- Передавать запрос BLE-сервиса существующему `exxpiano-wifi`; только Wi-Fi supervisor SHALL управлять `wlan0`, `wpa_supplicant` и откатом конфигурации.
- Разрешать BLE-настройку автоматически только у ещё не настроенного устройства в ограниченном временном окне; после сохранения сети повторное открытие SHALL требовать явного локального действия или команды из доступного web-интерфейса.
- Требовать защищённое BLE-соединение, ограничивать одну активную сессию и не сохранять и не журналировать открытый пароль Wi-Fi.
- Сохранить уникальную setup Wi-Fi и captive portal как fallback при отсутствии Bluetooth, несовместимом телефоне или неудачной BLE-настройке.
- Поддерживать встроенный BLE Raspberry Pi 3/4; для Raspberry Pi 2 явно требовать совместимый USB Bluetooth-адаптер и не блокировать setup Wi-Fi при его отсутствии.
- Включить BlueZ и BLE-службу в полный DietPi-образ; отсутствие Bluetooth-адаптера MUST NOT блокировать запуск фортепиано.
- Провести автоматические проверки протокола, секретов, таймаутов и отката, а также отдельную проверку на реальных Raspberry Pi 2 с USB-адаптером, Pi 3 и Pi 4 и на Android/iOS. Аппаратная проверка в рамках proposal остаётся невыполненной.

## Capabilities

### New Capabilities

- `network/bluetooth-provisioning`: обнаружение устройства, защищённый BLE-протокол настройки, мобильный клиент, жизненный цикл сессии и совместимость Bluetooth-адаптеров.

### Modified Capabilities

- `network/wifi-setup`: принимать проверенные запросы подключения от BLE-службы через существующий supervisor и сохранять setup Wi-Fi как fallback после ошибки или при отсутствии Bluetooth.

## Impact

- Новая системная служба и BLE-протокол рядом с `exxpiano-wifi`; изменения package/image dependencies, systemd, конфигурации и тестов.
- Новый мобильный клиент Android/iOS в отдельном каталоге проекта; Web Bluetooth не является обязательным клиентом.
- Потребуются BlueZ и D-Bus-интеграция на DietPi; web-сервер остаётся без новых зависимостей.
- Меняется пользовательский путь первоначальной настройки, но формат SD-образа, installation ID и формат `wpa_supplicant` сохраняются.
- Change согласован с деревом capabilities `<домен>/<capability>` (`network/wifi-setup`), введённым change `reorganize-spec-capability-tree`.
