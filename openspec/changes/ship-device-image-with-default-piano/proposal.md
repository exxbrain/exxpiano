# Proposal

## Why

Продуктом проекта является готовое устройство, поэтому основной результат сборки должен быть полным записываемым образом DietPi для Raspberry Pi с уже установленным фортепиано. Публикация отдельных `.deb` и отдельного ZIP/TAR.GZ-инсталлятора для установки поверх DietPi создаёт нецелевой сценарий самостоятельной установки и допускает получение устройства без звукового банка.

## What Changes

- **BREAKING**: исключить отдельные `.deb` и ZIP/TAR.GZ-инсталлятор для установки поверх DietPi из публичных результатов стандартной и релизной сборки.
- Сделать персональный записываемый SD-образ на базе DietPi для Raspberry Pi 2/3/4 ARMv8 основным поставляемым артефактом устройства.
- Выпускать отдельный персональный ZIP для каждого серийного номера платы; поставляемый образ MUST быть привязан к явно переданному serial, а непривязанный образ MUST NOT считаться продуктовым артефактом.
- Именовать поставляемый ZIP по формату `exxpiano-rpi234-v<версия>-dietpi-<версия-dietpi>-<номер>-sn-<serial>-sd.zip`, где версия продукта берётся из корневого файла `VERSION`, версия DietPi — из метаданных базового образа, номер нормализован по правилам реестра, а serial содержит полный нормализованный идентификатор платы из 16 строчных шестнадцатеричных символов. Невозможность определить версию DietPi MUST блокировать выпуск образа.
- Фиксировать версию и SHA-256 исходного образа DietPi также в README устройства и машиночитаемом манифесте сборки.
- Поставлять полный загрузочный образ, который записывается непосредственно на чистую SD-карту и уже содержит DietPi, приложение и обязательные звуковые банки.
- Включать в образ по умолчанию стандартный банк фортепиано и банк механики; отсутствие любого обязательного банка MUST блокировать выпуск образа.
- Убрать из продуктового сценария сборку и поставку образа без банков.
- Разрешить использовать `.deb` как внутреннюю деталь сборки образа, не объявляя его самостоятельным продуктовым артефактом.
- Обновить CI, тесты и русскую и английскую документацию под модель поставки готового устройства.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `provisioning-and-upgrades`: заменить поставку пакетов и отдельного инсталлятора поставкой полного персонального SD-образа с DietPi, который записывается на чистую карту, содержит работоспособное фортепиано и не выпускается без обязательных банков.

## Impact

- Затрагиваются сборщик полного SD-образа на основе официального образа DietPi, формат имён и манифестов персональных артефактов, сценарии пакетирования и отдельной установки поверх DietPi, CI-публикация, тесты сборки и пользовательская документация.
- Runtime-импорт пользовательских банков относится к отдельному change `import-banks-from-usb` и не влияет на состав, имя, манифест или критерии выпуска первоначального образа.
- Потребуются локальные или заранее подготовленные исходные банки; большие банки и производные файлы по-прежнему не должны отслеживаться в Git.
- Формат обновления уже работающих устройств остаётся отдельной задачей: внутреннее применение `.deb` допускается, пока не появится новый механизм обновления.
- Автотестами можно проверить обязательность serial, выбор банков, версию и serial в имени, метаданные DietPi, состав артефактов и отказ при неполной комплектации. Запуск образа, звук и первый старт MUST быть проверены на совместимых Raspberry Pi 2, 3 и 4; до такой проверки соответствующая модель остаётся непроверенной на оборудовании.
