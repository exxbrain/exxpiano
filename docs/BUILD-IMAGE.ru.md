# Как собрать образ SD-карты (по серийному номеру платы)

Этот документ для того, кто готовит устройства. Результат: один zip на плату Raspberry Pi 3, который записывается на карту и при включении сам настраивается.
Образ привязан к **серийному номеру платы**, на которую его ставят: номер и имя устройства, сеть настройки и QR-наклейка, запись в реестре.

## Что понадобится (один раз)

| Что | Зачем | Как |
|---|---|---|
| Mac (или Linux) с **Python 3** | сам скрипт | уже есть |
| **Docker Desktop**, запущенный | образ собирается в контейнере Linux | установите с docker.com, запустите; проверка: `docker info` |
| Банки звуков `.sf2` | пойдут в образ | `scripts/make-soundfonts.sh`, готовые лежат в `build/archive/` |
| Образ **DietPi** для Pi 2/3/4 (ARMv8, Trixie) | основа | скачайте `DietPi_RPi234-ARMv8-Trixie.img.xz` с https://dietpi.com/ (раздел Downloads) и положите, например, в `~/Downloads/` |
| Место на диске | образ примерно 1,5 ГБ, zip 0,5-1 ГБ на устройство | проверьте `df -h` |

Скачивать вручную проще и надёжнее. Флаг `--download` тоже есть (качает в `build/cache/` и проверяет контрольную сумму), но он не пробовался с настоящим сайтом.

## Шаг 1. Узнайте серийный номер платы

Серийный номер есть у каждой платы Raspberry Pi, он зашит в процессор. Его не нужно знать заранее, если вы не привязываете образ к плате (тогда пропустите шаг и шаг 3 с `--serial`).

- Плата работает с любой картой по SSH: `grep Serial /proc/cpuinfo` -> например `Serial : 00000000d2f2f1de`.
- Плата уже с нашим ПО: серийный номер показан на странице в разделе **Wi-Fi -> Имя устройства** и в `python3 /opt/piano-synth/deviceid.py`.

Запишите 16 цифр (можно и последние 8: `d2f2f1de`).

## Шаг 2. Один образ для одной платы

```bash
cd ~/Projects/pi-salamander-piano
python3 scripts/build-sd-image.py \
  --dietpi ~/Downloads/DietPi_RPi234-ARMv8-Trixie.img.xz \
  --piano build/archive/Salamander-stereo-6L-9s-v3.sf2 \
  --serial d2f2f1de --lock --number serial \
  --password 'пароль root, не короче 8 знаков' --ap-password 'пароль с наклейки, 8-63 знака' \
  --country RU --timezone Europe/Moscow --note 'для Ивана, 12.10'
```

Что значат параметры:

- `--serial` плата, для которой карта; без него образ универсальный, номер берётся из Wi-Fi-адреса при первом включении.
- `--lock` синтезатор **не запускается** на другой плате (без него только красное предупреждение на странице). Это учёт и защита от копирования карты на другую плату, а не стойкая защита: кто имеет root на устройстве, может отредактировать `/etc/piano-synth.conf`.
- `--number serial` номер устройства = последние 4 цифры серийного номера (`F1DE`); `--number auto` берёт следующий свободный (`0001`, `0002`...); можно задать вручную (`--number 0007`).
- `--password` общий пароль DietPi (root и dietpi). Если не задан, остаётся стандартный `dietpi`: **для устройства, которое вы отдаёте, обязательно задайте свой**.
- `--ap-password` пароль сети настройки `Piano-Setup-<номер>` (по умолчанию `pianosetup`, он же напечатан на наклейке).
- `--mech` банк механики (по умолчанию `build/archive/Salamander-mech.sf2`), `--no-banks` собрать без банков (поставить потом).
- `--dry-run` проверить всё и показать план, ничего не делая. **Начните с него.**

Первый запуск соберёт образ контейнера сборщика (минута). Сам образ собирается 1-3 минуты. В конце скрипт перечитывает образ и запускает его программы в контейнере как проверку.

## Шаг 3. Пакетная сборка по списку плат

Файл `boards.csv` (первая строка с названиями колонок обязательна, `number`, `name`, `note` необязательны, строки с `#` пропускаются):

```csv
serial,number,name,note
00000000d2f2f1de,,,Иван
00000000aaaabbbb,0042,piano-kitchen,Ольга
100000001234cdef,,,
```

```bash
python3 scripts/build-sd-image.py --dietpi ~/Downloads/DietPi_RPi234-ARMv8-Trixie.img.xz --piano build/archive/Salamander-stereo-6L-9s-v3.sf2 \
  --serials boards.csv --lock --password '...' --ap-password '...' --country RU --timezone Europe/Moscow
```

Всё проверяется до начала (повторы серийников и номеров, неверные значения). Если сборка упала посередине, скрипт назовёт готовые карты (они уже в реестре), остальное запустите снова.

## Что получится

В `dist/sd/<номер>/`:

- `piano-synth-<номер>-sd.zip` образ карты;
- `sticker/setup-codes-Piano-Setup-<номер>.html` наклейка с двумя QR-кодами (подключиться к сети и открыть страницу) и подписями; откройте файл в браузере и напечатайте;
- `README-<номер>.txt` что это за устройство, как записать, как называется.

И строка в реестре `registry/devices.csv` (номер, имя, серийный номер, версия, дата, контрольная сумма образа, банки, примечание). Реестр не попадает в git: делайте его копию. Команды: `python3 scripts/sd-registry.py list | show 0007 | find иван | note 0007 "продано 12.10"`.

## Шаг 4. Запишите карту и включите

1. **Raspberry Pi Imager**: «Choose OS» -> «Use custom» -> выберите zip (его не нужно распаковывать). Или **balenaEtcher**: «Flash from file» -> zip.
2. Вставьте карту в Pi, **подключите кабель Ethernet** (первая настройка самого DietPi один раз скачивает обновления), включите питание.
3. Подождите несколько минут (DietPi настраивается, карта расширяется). Затем устройство открывается по `http://piano-<номер>.local:8080/`, а без сети включает свою сеть `Piano-Setup-<номер>`: наведите камеру на QR-коды наклейки.

## Проверка и если что-то не так

- **Образ не запускался на настоящей Raspberry Pi** (весь конвейер проверен на образе-заменителе и в контейнере). Запишите первую карту, понаблюдайте за запуском и посмотрите `cat /var/log/piano-synth-firstboot.log` и `journalctl -u piano-synth -u piano-web -u piano-wifi`.
- На странице красная плашка «карта сделана для другой платы»: серийник платы не совпал с тем, что в образе. Если плату заменили, соберите новую карту для её серийника или уберите `DEVICE_SERIAL` из `/etc/piano-synth.conf`.
- `Docker is not running`: запустите Docker Desktop. `Cannot connect to the Docker daemon`: то же.
- Нет места: освободите диск; рабочие файлы сборки лежат в `build/sd-work/` (можно удалять).
- Остались занятые loop-устройства после аварии: `docker run --rm --privileged piano-sd-builder losetup -D`.
- Linux на x86 (не Mac с чипом Apple): для запуска программ arm64-образа нужны `qemu-user-static` и binfmt; на Mac с Apple Silicon это не нужно.
- Адрес DietPi на dietpi.com изменился: скачайте образ вручную и укажите `--dietpi`.
- Проверить сам сборщик без настоящего DietPi: `scripts/sd-fake-dietpi.sh` делает образ-заменитель, `scripts/sd-smoke-test.sh` запускает программы из готового образа.

## Обновление уже выданных устройств

Образ собирается один раз; обновлять работающее устройство можно по сети: `scripts/deploy-to-pi.sh <адрес>` (с откатом при неудаче). Новая версия ПО попадёт в следующие образы автоматически (версия берётся из `VERSION`).
