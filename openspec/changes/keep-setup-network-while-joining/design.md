# Design

## Context

См. `proposal.md`. Служба `exxpiano-wifi` единолично владеет `wlan0`: setup-сеть запускается через `hostapd` и `dnsmasq` на `wlan0` после `ifdown`, а подключение к домашней сети (`ifup`) возможно только после остановки точки доступа. При попытке подключения из setup-сети точка выключается сразу, при неудаче возвращается через `enter_ap`.

## Goals / Non-Goals

**Goals:**

- Не терять подключение телефона к setup-сети до успеха там, где это позволяет радиомодуль.
- Не ухудшать работу на неподдерживаемых чипах и без включённой опции.

**Non-Goals:**

- Сменить канал setup-сети под выбранную сеть (потребует перезапуска точки и обрыва телефона).
- Подключение к сети на 5 ГГц при setup-сети на 2,4 ГГц.
- Одновременное подключение к двум домашним сетям.

## Decisions

### 1. Опция, выключенная по умолчанию

Критичный путь первой настройки (setup-сеть) не меняется для всех плат ради неподтверждённого на железе режима. Включение — `WIFI_CONCURRENT=1`; пока режим не проверен на реальной плате, он остаётся экспериментальным.

### 2. Возможность определяется по `iw list`

Режим применяется, если в блоке `valid interface combinations` есть комбинация, где `AP` и `managed` — разные группы с лимитом не меньше одного (или общая группа с лимитом не меньше двух) и `total` не меньше двух. Альтернатива — определять по модели платы — отклонена: чип и прошивка важнее модели, а `iw` уже есть в зависимостях.

### 3. Виртуальный интерфейс `uap0`

Setup-сеть запускается на `uap0`, созданном командой `iw dev wlan0 interface add uap0 type __ap`; основной `wlan0` остаётся управляемым и не останавливается (`client_down` не вызывается). Адрес setup-сети и `dnsmasq` привязаны к `uap0`. При остановке `uap0` удаляется, `wlan0` не трогается. Любая ошибка создания возвращает к обычной setup-сети.

### 4. Условие «тот же канал»

У радиомодуля один канал на оба интерфейса. Режим применяется только когда канал сети из последнего сканирования (`channel_of(freq)`) равен `WIFI_AP_CHANNEL`. Скрытая сеть не имеет известного канала — прежний путь. Альтернатива — перезапускать точку на канале цели — отклонена, так как оборвала бы телефон, то есть то, чего пытается избежать изменение.

### 5. Порядок при успехе и неудаче

Успех: `ifup wlan0`, ожидание адреса и маршрута, затем остановка портала и точки без повторного `client_up`. Неудача: возвращаем файл сетей, `client_down` для `wlan0`, точка не затрагивается, результат публикуется.

## Risks / Trade-offs

- [Прошивка перестраивает канал точки под клиента, и телефон кратко теряет связь] → проверить на Pi; в документации указано как открытый вопрос; без опции ничего не меняется.
- [Сканирование при работающей точке нарушает работу точки] → сканирование выполняется только до запуска точки, в режиме точки используется кэш.
- [Условие «тот же канал» срабатывает редко (3 непересекающихся канала)] → пользователь может задать `WIFI_AP_CHANNEL` под свой роутер; смена канала под цель вынесена за границы.
- [Остаточный `uap0` после сбоя] → перед созданием удаляется старый `uap0`.

## Migration Plan

1. Добавить опцию, проверку возможностей и виртуальный интерфейс; существующее поведение без опции не меняется.
2. Включить на тестовой плате (`WIFI_CONCURRENT=1`, канал роутера в `WIFI_AP_CHANNEL`), проверить сценарии успеха и неверного пароля.
3. Если режим стабилен, обсудить включение по умолчанию отдельным change.
4. Откат — выключить опцию; данные не затрагиваются.

## Open Questions

Нет вопросов, меняющих состав работ; поведение радиомодуля подтверждается только на реальной плате (задача 3.1).
