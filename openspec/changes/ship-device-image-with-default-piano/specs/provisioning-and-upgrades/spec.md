# Spec Delta

## MODIFIED Requirements

### Requirement: Персональный SD-образ

Система SHALL создавать для каждого устройства полный загрузочный ZIP-образ на базе DietPi RPi 2/3/4 ARMv8 с именем `exxpiano-rpi234-v<версия>-dietpi-<версия-dietpi>-<номер>-sn-<serial>-sd.zip`, предназначенный для непосредственной записи на чистую SD-карту и содержащий уникальный номер, полный нормализованный serial платы, hostname, setup SSID, установленное приложение, предустановленные стандартный банк фортепиано и банк механики, README, машиночитаемый манифест, печатную наклейку и запись в локальном реестре. Версия продукта в имени SHALL браться из корневого файла `VERSION`, версия DietPi SHALL читаться из метаданных базового образа и приводиться к безопасному для имени файла виду, а serial SHALL состоять из 16 строчных шестнадцатеричных символов. README и манифест SHALL содержать ту же версию и SHA-256 исходного образа DietPi. Система MUST NOT выдавать образ как готовый, если serial не передан, версия DietPi не определена, DietPi, приложение или хотя бы один обязательный банк отсутствует либо не прошёл проверку сборки.

#### Scenario: Чистая SD-карта

- **WHEN** оператор записывает поставляемый ZIP-образ на чистую совместимую SD-карту и устанавливает её в поддерживаемую образом DietPi RPi234 ARMv8 Raspberry Pi 2, 3 или 4
- **THEN** карта содержит загрузочную DietPi, установленное приложение и обязательные банки без предварительной установки ОС или копирования отдельного инсталлятора

#### Scenario: Имя образа однозначно определяет сборку и плату

- **WHEN** персональная сборка устройства успешно завершена
- **THEN** ZIP имеет имя `exxpiano-rpi234-v<версия>-dietpi-<версия-dietpi>-<номер>-sn-<serial>-sd.zip`, где версия продукта совпадает с `VERSION`, версия DietPi — с метаданными основы, а нормализованные номер и serial совпадают с внутренними данными образа, README, манифестом и реестром

#### Scenario: Сборка партии

- **WHEN** оператор передаёт список из нескольких серийных номеров плат
- **THEN** система создаёт для каждого serial отдельный персональный ZIP с собственными номером, именем и сопутствующими материалами

#### Scenario: Серийный номер не передан

- **WHEN** оператор запускает производственную сборку без `--serial` или `--serials`
- **THEN** система завершает сборку ошибкой до создания образа и записи в реестр

#### Scenario: Прослеживаемость основы DietPi

- **WHEN** персональная сборка устройства успешно завершена
- **THEN** имя ZIP, README и машиночитаемый манифест содержат одну и ту же версию DietPi, а README и манифест дополнительно содержат SHA-256 исходного образа

#### Scenario: Версия DietPi не определена

- **WHEN** метаданные базового образа не содержат пригодную для имени версию DietPi
- **THEN** система завершает сборку ошибкой, не выдаёт ZIP как готовый и не добавляет успешную запись в реестр

#### Scenario: Сборка с банками по умолчанию

- **WHEN** оператор запускает сборку устройства без явного выбора звуковых банков
- **THEN** система использует стандартные банки фортепиано и механики и включает их в записываемый образ

#### Scenario: Явная замена банков

- **WHEN** оператор передаёт совместимые банки фортепиано и механики явно
- **THEN** система использует их вместо стандартных банков и фиксирует выбранные банки в данных сборки устройства

#### Scenario: Обязательный банк отсутствует

- **WHEN** стандартный или явно выбранный банк фортепиано либо механики отсутствует или непригоден для включения в образ
- **THEN** система завершает сборку ошибкой, не выдаёт ZIP-образ как готовый и не добавляет успешную запись в реестр

#### Scenario: Автоматический номер

- **WHEN** сборка запрошена с `--number auto`
- **THEN** система выбирает следующий свободный нормализованный номер и использует его во всех артефактах устройства

#### Scenario: Неудачная сборка

- **WHEN** подготовка или smoke test образа завершается ошибкой
- **THEN** система не добавляет успешную запись в реестр и сохраняет диагностируемый результат сборки

#### Scenario: Секреты сборки

- **WHEN** образу передаются root-пароль и пароль setup-сети
- **THEN** сборщик передаёт их во внутреннюю среду, не включает в аргументы команд и не записывает в журнал

### Requirement: Проверка и публикация сборок

CI SHALL запускать автоматические тесты и проверять конвейер формирования полного DietPi-образа для push и pull request. Публичные CI-артефакты и релизы MUST NOT содержать отдельные Debian-пакеты или ZIP/TAR.GZ-инсталлятор для установки поверх DietPi, а готовые образы устройств SHALL формироваться управляемой персональной сборкой с DietPi, приложением и обязательными банками; релизный тег MUST совпадать с файлом `VERSION`.

#### Scenario: Проверка изменения

- **WHEN** выполняется CI для push или pull request
- **THEN** система запускает автоматические тесты конвейера полного DietPi-образа и не публикует `.deb` или отдельный инсталлятор как продуктовые артефакты

#### Scenario: Несовпадающий релизный тег

- **WHEN** tag build использует версию, отличную от `VERSION`
- **THEN** публикация релиза завершается ошибкой до прикрепления артефактов

#### Scenario: Выпуск устройства

- **WHEN** оператор успешно завершает персональную сборку устройства
- **THEN** поставляемым программным артефактом является записываемый на чистую SD-карту ZIP-образ с DietPi, приложением, обязательными банками и сопутствующими материалами конкретного устройства

## REMOVED Requirements

### Requirement: Debian-пакеты

**Reason**: Отдельный Debian-пакет не соответствует модели поставки готового устройства и создаёт неподдерживаемый самостоятельный сценарий установки.

**Migration**: Для новых устройств использовать персональный SD-образ. Сборка `.deb` может временно оставаться внутренним этапом формирования образа и обновления уже выданных устройств, но такой файл не публикуется как продукт.

### Requirement: DietPi-инсталлятор

**Reason**: Отдельный ZIP/TAR.GZ-инсталлятор для установки поверх уже подготовленной DietPi допускает установку приложения без фортепиано, тогда как поставляемое устройство должно быть полностью укомплектовано.

**Migration**: Вместо отдельного инсталлятора оператор собирает и записывает на чистую карту полный персональный SD-образ, уже содержащий DietPi, приложение и обязательные банки.
